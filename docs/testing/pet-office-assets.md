# Pet Office asset admission

Immutable project/global visual selections can be sampled without attaching an
overlay or advancing animation. Custom Pet reads hold the storage read permit
only while capturing bounded immutable bytes, releasing it before inspection,
hashing and cache admission. Canonical homes or verified migration targets are
allowed; links beneath the physical Pet root, traversal and concurrently changed
files fail closed. No local paths or asset identifiers enter wire metadata.

The cache admits at most eight images and 16 MiB, with 4 MiB per image. Busy
migration preserves a previously admitted image when possible. Configuration
generation, file identity/stamp and digest fence stale data. Metadata codecs
validate participant source ownership, dimensions, action mapping and limits.
Publisher snapshots retain only live source selections and recheck configuration
before exposing immutable bytes. Transport and scene rendering remain separate.

Temporary-root tests cover migration read exclusion, stable capture, symlink/path
rejection, verified Windows junction migration, cache limits and exact metadata.
No real user Pet or configuration directory is written during validation.
